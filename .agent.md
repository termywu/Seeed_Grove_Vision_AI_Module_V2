# Seeed Grove Vision AI Module V2 Development Guide

This repository contains firmware examples and development tools for the **Seeed Grove Vision AI Module V2**, featuring the Himax WiseEye2 (WE2) AI processor with ARM Cortex-M55 and Ethos-U55 NPU for edge AI applications.

## Project Overview

### Hardware Platform
- **Processor**: Himax WiseEye2 (WE2) with ARM Cortex-M55 and Ethos-U55 NPU
- **Target Device**: Seeed Grove Vision AI Module V2
- **Memory**: Support for external PSRAM and flash memory
- **Sensors**: Camera sensors (HM01B0, HM0360, HM11B1, HM2140, etc.), IMU (ICM42688), PDM microphones
- **Package Options**: LQFP128, WLCSP65, QFN88, BGA64
- **Interfaces**: UART, SPI, I2C, I2S, GPIO

### Software Stack
- **Languages**: C/C++ (embedded firmware)
- **Build System**: GNU Make with cross-compilation support
- **Toolchains**: ARM Compiler 6, GNU ARM Embedded Toolchain
- **RTOS**: FreeRTOS 10.5.1 with TrustZone security support
- **AI Framework**: TensorFlow Lite Micro with CMSIS-NN 7.0.0 optimization
- **Libraries**: CMSIS-DSP, CMSIS-CV, Audio processing, Image processing, JPEG encoding
- **Security**: ARM TrustZone, Secure Boot, Hardware crypto acceleration

## Development Workflow

### Building Firmware

#### Using Docker (Recommended)
```bash
# Build using Docker container
./build.sh

# Build specific target
./build.sh clean all
```

#### Manual Build
```bash
cd EPII_CM55M_APP_S
make clean all
```

### Flashing Firmware

#### Prerequisites
```bash
# Install Python dependencies
pip install -r xmodem/requirements.txt

# Set device permissions (Linux)
sudo setfacl -m u:[USERNAME]:rw /dev/ttyACM0
```

#### Flash Command
```bash
# Flash firmware and model
python3 xmodem/xmodem_send.py \
  --port=/dev/ttyACM0 \
  --baudrate=921600 \
  --protocol=xmodem \
  --file=we2_image_gen_local/output_case1_sec_wlcsp/output.img \
  --model="model_zoo/tflm_yolov8_od/yolov8n_od_192_delete_transpose_0xB7B000.tflite 0xB7B000 0x00000"
```

### Model Integration

#### Model Placement
- Models are stored in flash memory starting from address `0x200000`
- First 2MB (0x000000-0x200000) reserved for firmware
- Model addresses must be 4KB aligned
- Define model addresses in `common_config.h` files (e.g., `YOLOV8_OBJECT_DETECTION_FLASH_ADDR`)
- Use Vela-optimized models for Ethos-U55 NPU acceleration

#### Model Zoo Structure
- `model_zoo/[app_name]/` - Contains TensorFlow Lite models
- Models are pre-quantized (INT8) and Vela-optimized for target hardware
- Naming convention includes memory address (e.g., `yolov8n_od_192_delete_transpose_0xB7B000.tflite`)
- Multiple models can be flashed simultaneously to different addresses

#### Model Optimization
- Use Vela compiler for Ethos-U55 NPU optimization
- Quantize models to INT8 for memory efficiency
- Remove unnecessary operations (e.g., transpose layers)
- Consider model size constraints (limited flash space)

## Best Practices and Conventions

### Code Organization
- Keep application-specific code in `app/scenario_app/[app_name]/`
- Use `common_config.h` for application-specific configurations
- Follow existing naming conventions for consistency
- Separate hardware abstraction from application logic
- Use `.mk` files for modular build configuration
- Implement `cvapp_*.cpp` for computer vision processing logic

### Memory Management
- Be mindful of memory constraints (limited SRAM)
- Use external PSRAM for large data structures
- Optimize model sizes using quantization and pruning
- Define memory layouts in linker scripts (`.ld` for GCC, `.sct` for ARM)
- Consider TCM (Tightly Coupled Memory) for performance-critical code
- Use `memory_manage.c` for dynamic memory allocation strategies

### Security Considerations
- Use TrustZone for secure/non-secure partitioning
- Implement secure boot for production deployments using `secureboot_tool/`
- Store sensitive data in secure memory regions
- Use hardware crypto acceleration (CC312 cryptographic engine)
- Configure Memory Protection Controller (MPC) and Peripheral Protection Controller (PPC)
- Use Non-Secure Callable (NSC) functions for secure/non-secure communication

### Performance Optimization
- Enable CMSIS-NN 7.0.0 for neural network acceleration
- Use Ethos-U55 NPU for inference acceleration with Vela-optimized models
- Optimize data paths for camera and sensor processing using sensordp library
- Consider power management for battery-powered applications
- Use Helium (MVE) instructions for SIMD operations
- Enable compiler optimizations (`OLEVEL = O2`)

### Audio Processing
- Use PDM (Pulse Density Modulation) for microphone input
- Implement MFCC (Mel-Frequency Cepstral Coefficients) for audio feature extraction
- Use I2S interface for high-quality audio
- Consider VAD (Voice Activity Detection) for power optimization

### Camera Integration
- Support multiple camera sensors (HM01B0, HM0360, HM11B1, HM2140)
- Use CSI (Camera Serial Interface) for high-speed camera data
- Implement image preprocessing in hardware (HW2x2, HW5x5)
- Use JPEG encoding for image compression
- Configure Test Pattern Generator (TPG) for testing

### Testing and Debugging
- Use SWD debugging tools in `swd_debugging/` with pyOCD
- Enable debug logging with `DBG_APP_LOG` and `FRAME_CHECK_DEBUG`
- Test with Himax AI web toolkit for UART visualization
- Validate models with known test datasets
- Use `hardfault_handler.c` for crash debugging
- Monitor performance with built-in profiling tools

### Version Control
- Keep generated files out of version control (`obj_*`, `bin/`, `*.img`)
- Use `.gitignore` for build artifacts and temporary files
- Document model versions and training parameters
- Tag releases with firmware and model versions
- Use git submodules for external dependencies

## Common Issues and Solutions

### Build Issues
- **Toolchain Path**: Ensure correct toolchain path configuration in makefile (`ARM_TOOLPATH`, `GNU_TOOLPATH`)
- **Missing Dependencies**: Check makefile variables for target platform and verify all dependencies are installed
- **Linker Errors**: Clean build directory (`make clean`) if encountering link errors
- **Memory Overflow**: Adjust linker script memory sections if code/data doesn't fit
- **CMSIS-NN Version**: Ensure `LIB_CMSIS_NN_VERSION` matches your model requirements (7_0_0 vs default)

### Flashing Issues
- **Device Permissions**: Set proper permissions (`sudo setfacl -m u:[USERNAME]:rw /dev/ttyACM0`)
- **Bootloader Mode**: Ensure device is in bootloader mode (hold boot button while resetting)
- **COM Port**: Verify correct COM port identification (`/dev/ttyACM0` on Linux, `COM#` on Windows)
- **Cable Quality**: Check USB cable connections and power supply stability
- **Reset Sequence**: Always reset device after successful flash operation
- **XMODEM Protocol**: Ensure XMODEM dependencies are installed (`pip install -r xmodem/requirements.txt`)

### Model Issues
- **Vela Optimization**: Verify model is Vela-optimized for Ethos-U55 NPU
- **Memory Constraints**: Check model size fits in allocated flash space (models start at 0x200000)
- **Address Alignment**: Ensure model address alignment (4KB boundaries)
- **Quantization**: Validate model format and INT8 quantization
- **Model Loading**: Check `common_config.h` for correct model flash addresses
- **NPU Compatibility**: Ensure model operations are supported by Ethos-U55

### Runtime Issues
- **Memory Allocation**: Monitor SRAM usage and use external PSRAM for large buffers
- **Performance**: Enable compiler optimizations and use hardware acceleration
- **Power Management**: Configure appropriate power modes for your use case
- **Sensor Configuration**: Verify camera sensor initialization and clock settings
- **Audio Processing**: Check PDM configuration and sampling rates for audio applications
